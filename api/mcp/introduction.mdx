## Endpoints

MCP is available via:

- API host prefix: `https://api.receiptor.ai/mcp`
- Dedicated MCP host root: `https://mcp.receiptor.ai`

## Protocol

- Transport: Streamable HTTP
- Payload format: JSON-RPC 2.0
- Tool registration: dynamic from backend capability registry
- Tool metadata: human-readable titles plus MCP annotations for read-only and destructive hints
- Protocol version is negotiated during `initialize`

## Public methods

No bearer token required:

- `initialize`
- `notifications/initialized`
- `notifications/cancelled`
- `tools/list`
- `prompts/list`
- `resources/list`
- `ping`

## Public native tool

The native `get_server_info` tool is callable without OAuth so clients can verify connectivity before auth.

## Protected tool calls

Most `tools/call` requests require an OAuth bearer token.

There are two important exceptions in behavior:

- `get_server_info` is public
- `workspace_get_context`, `workspaces_list`, and `workspace_switch` can run before an org is selected for the current OAuth session

For non-bootstrap capability tools, the current plan must include `mcp_access`.

## Tool naming

Capability tools are generated from capability slugs by replacing `.` with `_`.

Examples:

- `documents.search` -> `documents_search`
- `workspaces.list` -> `workspaces_list`

## Native MCP-only tools

- `get_server_info`
- `workspace_get_context`
- `workspace_switch`

`workspace_switch` validates the target workspace and updates the active workspace for the current OAuth session.
Re-authorize only if the client loses its OAuth session or cannot complete the switch flow.
